# Smoke review response template

This template is optional. A free-form response is equally useful.

```yaml
reviewer: ""
affiliation: ""
system_or_framework: ""
case_id: LC000
applicability: applicable | partial | not-applicable | unclear
system_native_mechanism: ""
expected_outcome: ""
decision_phase: ""
decision_owner: ""
policy_explicit: ""
main_objection: ""
closest_prior_art: ""
recommended_change: ""
may_attribute: yes | no | ask
follow_up_ok: yes | no
```

## Fast path

If you only answer one thing:

> **Which ONE case is wrong or unfair for your architecture, and what assumption should change?**

The benchmark author can turn a substantive comment into a proposed issue/spec change and ask you only to verify the interpretation.
